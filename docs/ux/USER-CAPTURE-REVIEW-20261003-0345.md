## 0. 방법과 신뢰 수준

- 이미지는 **픽셀 값을 직접 측정**했다(좌표·RGB). 영상은 2fps/5fps로 프레임을 뽑아 같은 방식으로 측정했고, 장면 내용은 영상 모델에 별도 요청했다(§6 참고).
- 아이콘 모양(어떤 기호인지)은 시각 모델 설명이 서로 모순되었다(예: 같은 버튼을 "Fast Forward"·"Next"·"Equalizer·Gear"로 다르게 묘사). **아이콘 모양에 대한 서술은 신뢰하지 않고 이 문서의 근거에서 제외했다.** 버튼 위치·크기·색은 픽셀 측정이라 신뢰한다.
- 화면 배율: 버튼 폭이 50px로 측정됨 → XAML 40 DIP 기준 **배율 125%**.
- 프레임 시각은 5fps 기준 `t = (프레임번호-1)/5` 초. 이동 감지 근거는 프레임 간 영상 영역 차이(움직임)와 시크 썸 위치.

## 3. U2 (재생/일시정지 통합) 확인 근거

- 코드(`MainWindow.xaml`)에 별개 버튼 `PlayButton`·`PauseButton`이 있음(갭표 §1).
- 영상 근거: 재생 중(t≈2.8s)과 정지 중(t≈9.0s)의 Play·Pause·Stop 버튼 영역 픽셀 차이가 0.26~0.41(압축 잡음 수준) → **재생 상태가 바뀌어도 어느 버튼의 모습도 변하지 않음.** (아이콘 모양 자체는 별도로 판독하지 않음.)
- 결론: U2는 **확인됨** (코드 + 영상 픽셀). 단일 토글 필요 판단은 변동 없음.

1. **03b**: 재생 중 마우스를 영상 가운데로 옮겨 멈추고 3초 뒤 chrome이 사라진 상태, 이어서 바 위로 마우스를 가져가 클릭할 때 chrome이 나타나는 5~10초 영상 (U1 재현용). "사라진 뒤 바를 클릭했을 때"와 "바 위에서 가만히 있다가 사라질 때"를 각각.
2. **04c**: Tab 키로 포커스 이동 한 장 (포커스 표시 유무).
3. **07**: 창을 가장 좁게 줄인 한 장.
4. **05a**: 볼륨 OSD 한 장.
5. 02 정지 사진 한 장(구분 가능하게 정지 후 chrome이 보이는 상태).
6. 빌드 폴더 이름, PC 사양은 지금 없음 → 알려 달라고 요청.
(06 전체화면, 09 테마, 05b 자막은 Batch 1 필수가 아니므로 후순위.)

## 8. 정리

- **확정(픽셀 측정)**: 비활성·hover·pressed 색이 어두운 UI와 충돌(7), 숨김 시 #121212 띠(9), 슬라이더 트랙이 밝은 기본 모양(11), U2.
- **확인 못 함**: U1 재현, 포커스 표시, 좁은 창, OSD, 전체화면, 테마, 아이콘 글리프 품질.
- 검토 표의 판정은 Visual PASS 평가가 아니며, 구현 범위는 총괄 Gate 결정에 따른다. Batch 1 후보(U1·U2)와 별개로 7·9·11 항목은 Batch 2 이후 설계 문서 소재.
